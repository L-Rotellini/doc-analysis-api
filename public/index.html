Aucune demande pour l'instant.

Comment ça marche ?
  1. Le formulaire appelle POST /requests. AdonisJS insère la demande en base via Kysely (status: pending).
  2. L'API dépose un job BullMQ dans Redis et répond 202 Accepted tout de suite.
  3. Un worker séparé (node ace worker:start) consomme le job, simule l'analyse (2 s), puis met à jour la ligne en status: analyzed.
  4. Cette page interroge GET /requests chaque seconde pour montrer le basculement en direct.
  5. Le bandeau en haut lit l'état temps réel de BullMQ (waiting / active / completed + présence d'un worker via getWorkers()), indépendamment de la liste plus bas qui montre l'état persisté en base (pending / analyzed). La pastille worker peut mettre quelques secondes à passer "hors ligne" : BullMQ se base sur des heartbeats, c'est attendu.
  6. Le bouton Pause appelle analysisQueue.pause() : la file arrête de distribuer les jobs, mais le worker reste connecté — d'où la pastille amber "en pause" plutôt que grise "hors ligne". Les jobs existants finissent, les nouveaux s'empilent en waiting. C'est la primitive prévue pour les maintenances et déploiements, distincte d'un vrai arrêt du process.
